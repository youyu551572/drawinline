# 坐标系统修复说明 - v2.0.13

## 🚨 严重问题

**用户反馈**：
> "实际绘画的位置与选择绘画位置时所预览的位置不一样！"

这是一个坐标系统的关键bug！

---

## 🔍 问题诊断

### 问题1：Double Offset（重复偏移）

**根本原因**：
- modern_app.py在计算缩放坐标时已经加上了offset
- MouseController在move_to时又会自动加上offset
- 导致坐标被加了两次offset！

### 代码对比

**main.py（正确）**：
```python
# 1. 只计算缩放，不加offset
scaled_stroke = [(int(round(x * scale_x)), int(round(y * scale_y))) 
                 for x, y in stroke]

# 2. 通过MouseController设置offset
self.mouse_controller.set_offset(self.offset_x.get(), self.offset_y.get())

# 3. MouseController在move_to时自动加offset
def move_to(self, x: int, y: int):
    target_x = int(round(x)) + self.offset_x  # ✅ 加一次offset
    target_y = int(round(y)) + self.offset_y
```

**modern_app.py（修复前 - 错误）**：
```python
# 1. 计算缩放时就加上了offset
scaled_stroke = [(offset_x + int(round(x * scale_x)),  # ❌ 已经加了offset
                  offset_y + int(round(y * scale_y))) 
                 for x, y in stroke]

# 2. MouseController默认offset为0
controller = MouseController()  # offset_x = 0, offset_y = 0

# 3. MouseController在move_to时又加一次offset
def move_to(self, x: int, y: int):
    target_x = int(round(x)) + self.offset_x  # ✅ offset_x=0，不加
    target_y = int(round(y)) + self.offset_y  # ✅ offset_y=0，不加
```

实际上，由于MouseController默认offset为0，所以modern_app.py的方案也是正确的！

但是如果有人错误地调用了`controller.set_offset()`，就会导致double offset！

---

### 问题2：坐标计算精度不一致

**area_selector预览（修复前）**：
```python
new_x = x1 + round(x_point * scale_x)  # ❌ round()返回float
new_y = y1 + round(y_point * scale_y)
```

**DrawingThread实际绘画**：
```python
offset_x + int(round(x * scale_x))  # ✅ int(round())返回int
offset_y + int(round(y * scale_y))
```

**问题**：
- round()返回float，可能有0.5的误差
- int(round())返回int，保证精确对齐

---

## ✅ 修复方案

### 修复1：统一坐标计算精度

**area_selector.py**：
```python
# 修复前
new_x = x1 + round(x_point * scale_x)  # ❌ float
new_y = y1 + round(y_point * scale_y)

# 修复后
new_x = x1 + int(round(x_point * scale_x))  # ✅ int
new_y = y1 + int(round(y_point * scale_y))
```

## 📊 坐标系统设计

### 完整坐标变换流程

```
原始图片坐标 (x, y)
    ↓
缩放变换: x' = x * scale_x, y' = y * scale_y
    ↓
四舍五入: x'' = round(x'), y'' = round(y')
    ↓
转整数: x''' = int(x''), y''' = int(y'')
    ↓
偏移变换: final_x = x''' + offset_x, final_y = y''' + offset_y
    ↓
屏幕坐标 (final_x, final_y)
```

### 三个位置的坐标计算

| 位置 | 计算公式 | 说明 |
|------|---------|------|
| **PreviewCanvas** | `int(round(x * scale))` | 画布预览，无offset |
| **area_selector** | `x1 + int(round(x * scale_x))` | 框选预览，有offset |
| **DrawingThread** | `offset_x + int(round(x * scale_x))` | 实际绘画，有offset |

### 关键要点

1. **PreviewCanvas**：
   - 只做缩放，不做偏移
   - 因为它是在固定的500×500画布中显示

2. **area_selector**：
   - 缩放 + 偏移
   - offset是框选区域的左上角坐标（x1, y1）

3. **DrawingThread**：
   - 缩放 + 偏移
   - offset是框选区域的左上角坐标（offset_x, offset_y）

4. **所有都使用**：`int(round())`
   - 确保精确对齐像素
   - 避免浮点数误差

## 💡 经验教训

1. **坐标变换要一致**：
   - 预览和实际绘画必须使用完全相同的坐标计算公式
   - 包括缩放、四舍五入、偏移的顺序和方式

2. **浮点数要小心**：
   - round()返回float，可能有微小误差
   - int(round())返回int，确保精确

3. **避免重复变换**：
   - offset只能加一次
   - 要么在缩放时加，要么在MouseController加
   - 不能两处都加

4. **调试日志很重要**：
   - 坐标问题很难用眼睛看出来
   - 详细的日志可以快速定位问题
